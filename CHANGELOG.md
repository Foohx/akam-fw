# Changelog

## Unreleased: project renamed from Camyn to Akam

### Added

- **Native assistant binary, phase P3** (`tools/assistant`, experimental, not yet checked on a real camera or card). New commands: `backup` (double read over the maintenance telnet, nc transfer with size and hash checks, hardware verdict), `flash` and `restore` through the telnet + card route (the `YES` of the camera's script is sent only after the explicit yes), `find-camera` telnet detection (stock or Akam with the maintenance card), `prepare-backup-sd`, `prepare-flash-sd`, `wipe-sd`. Built in: a telnet client (`internal/camera/telnet`: marker-wrapped commands, manual mode, RFC 854 refusals) and a microSD writer (`internal/sdcard`: guards on `/sys`, MBR + FAT32 written directly on the device, read-back verification, wipe) whose privileged part is `akam sd-helper`, re-executed with sudo or pkexec after a red box and a second yes/no. The camera-side scripts it uploads are now embedded (`internal/assets`, `go generate`, drift test) and the program no longer searches the working directory for a checkout. Fake stock camera and image-file card tests; `image` stays in bash.
- **Native assistant binary, phase P2** (`tools/assistant`, experimental, not yet checked on a real camera). New commands: `get-kit` (HTTPS-only download with redirects checked, SHA256SUMS, OpenSSH SSHSIG signature check built in and cross-tested against `ssh-keygen -Y` both ways, the archive rules and MANIFEST checks of `verify_kit.sh`, the same refusal of a signed kit while `allowed_signers` has no key, the same unsigned-kit consent), `update` (SSH reflash of a running Akam camera: the steps of `reflash_over_ssh.sh` in Go, camera-side scripts unchanged, second Dropbear on port 2222, detached flash, polled log, independent read-back md5), `restore` (same path with the stock APP of your backup) and `verify` (SSH, `akam_hwcheck.sh`, ports, Wi-Fi gate, power-cycle by hand, same checks without the card). Every flash goes through one audited function (`internal/flash`) that needs an explicit yes (default No, refused without a terminal, bound to the image md5) and supports `--dry-run`; the program never reboots or power-cycles the camera and tells you to do it by hand; the other code paths keep refusing every flash command. `image` and the telnet/card routes stay in the bash wizard: the squashfs spike found no mature Go writer (specs/09, 10.2). The `xz` program is needed to open a kit. Tests: fake camera with a second Dropbear and a fake flash (full update, sha256 and read-back mismatch, interrupted upload, user says No, no terminal, dry run), the kit refusal cases ported from `verify_kit.sh` with verdict parity checked against the script on 25 kits.
- **P1 gaps (specs/10 G05 to G10 and G14)**, all checked on the host only, none on a camera yet:
  **port 8091 privacy (G05):** `LOG` lines go only to the camera itself or while debug mode is on, and `net.ssid` and `net.mac` read as `hidden` for other machines unless debug mode is on (`net.ip` stays readable). **A second RTSP client (G06)** is answered at once with `503 Service Unavailable` (`CSeq` echoed, `Retry-After: 10`) and closed, instead of waiting in the accept queue for the first viewer to leave; the first client and the video timing are not touched (`rtsp_busy.[ch]`, polled from the session loop, no extra thread); several viewers: restream with go2rtc. **Audio (G07):** the capture is supervised, after 5 read errors it is closed and reopened after 1, 2, 4 ... 60 s instead of stopping for good, and a failed open at start is retried; new persistent key `audio.mic_enable` and `./akam audio mic on|off`: off never opens the microphone and the stream has no audio track at all (needs a reboot to apply). **Time (G08), opt-in:** `./akam ntp [status | set SERVER... | off]` (1 to 3 validated servers in `/etc/config/akam/ntp`, camera helper `akam_ntp.sh` started by the wrapper only when that file exists, one-shot BusyBox `ntpd -q` at low priority, retried until the clock is 2024 or later, then every 6 h; default off, no traffic) and the metric `sys.time_set` on 8091. **RAM logs (G09):** every `/tmp/akam_*.log` is capped (100 lines or 64 KiB, trimmed in place, also the one Dropbear fills). **Wakeups (G10):** microphone off removes about 62 wakeups per second; the 20 ms drain poll and the audio on-demand ideas are documented in specs/10 as needing hardware measurements (they would touch the capture clock and the amplifier), and `akam_hwcheck.sh` prints the measured `wakeups N/s`. **`akam_hwcheck.sh` (G14)** audits UDP listeners (68, 3702 with ONVIF on, ephemeral client ports; anything else FAIL) and every running process against an allow-list (`msgserver` and `cmdserver` are WARN "vendor daemon, review"). Tests: `tests/native/rtsp_busy_test.c`, `audio_sup_test.c`, `tests/akam_ntp_test.sh`, `wizard_ntp_test.sh`, and the control, ctl_sys, audio_out, rtsp_sdp, rtsp_backchannel, wizard_audio, lockdown and hwcheck tests. Needs hardware: the unseen behaviour of the audio driver after a re-open and with the microphone off, `ntpd -q` from a 1970 clock, VLC plus `ffprobe` at the same time, the real UDP and process list.
- **Saved video settings, `./akam video` (specs/10 G11, items 1 and 3; needs hardware validation)**. `/etc/config/akam/video` (mode 0600, atomic, removed when everything is default) holds `bitrate=` (500 to 3000 kbit/s, the VBR+ ceiling, default 1536), `fps=` (10 or 15, default 15) and `gop=` (key frame interval in seconds, 1 to 4, default 2, sent to the encoder as seconds times fps frames). Read once at start (`video_cfg.[ch]`, before the ISP frame rate is set), used for the encoder (`venc.c`), the sensor frame rate and VTS (`ae.c`, and `night.c` for the day side: 15 fps / VTS 2284 or 10 fps / VTS 3426, the two pairs the code already sent), the capture clock, the bitrate window and the IDR wait (`rtsp.c`), and the ONVIF Media reports (`GetProfile(s)`, `GetVideoEncoderConfiguration(s)`, its Options, `GetVideoSources`). With no file nothing changes: same encoder parameters and byte-identical ONVIF goldens. 8091 keys `video.bitrate_cfg`, `video.fps_cfg`, `video.gop_cfg` and read-only `video.cfg_pending` (`video_ctl.[ch]`; loopback SET only, a network SET is refused; they do not clash with the measured `video.bitrate` and `video.fps_actual`). `./akam video [show | bitrate N | fps N | gop N]` sets them over SSH, says "applies at the next restart of the video service" and offers (default No) to run `kill the ak_rtsp pid` so the wrapper respawns it. The software watchdog limit (30 s without a frame) is wall-clock, with a compile-time check that it stays at least 100 frame periods at 10 fps. Not offered: resolution (ISP crop, VI formats and the encoder DMA pool exist for 1920x1080 only) and flip/mirror (only the ioctl number is known). Tests: `tests/video_cfg_test.sh`, `tests/wizard_video_test.sh`, `tests/onvif_media_test.sh` (configured values), `tests/control_test.sh`.
- **ONVIF wiring (specs/10 section 1)**: `ak_rtsp` now starts the ONVIF HTTP server and WS-Discovery from the opt-in flag file `/etc/config/akam/onvif` (`onvif_cfg.[ch]`: strict parser, exactly `enabled=` and `port=`, ports 21-24, 554 and 8091 refused, anything invalid or absent = off with one log line). Started after the video and the RTSP listener are up, so it never delays them; stopped on the error path. `ak_rtsp ctl ONVIF reload` (loopback only) re-reads the file and starts, stops or moves the services at run time without touching the video and answers `OK onvif.state=<state>`; `GET onvif.state` (and `LIST`) says `off`, `on:<port>`, `no_password` (enabled, password on, no valid clear-text credentials: nothing started) or `error:<reason>` (`port_in_use` ...). With the RTSP password OFF the service starts (reads open, writes refused, spec 3.3). Off: no thread, no socket. On: two threads, the HTTP poll has no timeout when idle and WS-Discovery ticks every 30 s. Device scopes (Profile Streaming and S, name from the hostname, hardware AK3918AV130, location) are rebuilt at each reload; XAddrs are computed per client. `arm_atomics.S` gains `__sync_lock_test_and_set_4` (needed once `http_srv.c` is linked). Tests: `tests/onvif_svc_test.sh` (parser, state machine, port in use, end-to-end GetSystemDateAndTime/GetDeviceInformation and a WS-Discovery Probe), `tests/control_test.sh` (remote reload refused, `onvif.state`). Not yet checked on hardware.
- **Native assistant binary, phase P1** (`tools/assistant`, Go, experimental; specs/09). One static executable (6.3 MiB amd64, 5.9 MiB arm64, starts in about 2 ms, MIT/BSD modules fetched by `tools/build/bootstrap.sh` into `tools/.toolchain/go` (checked by `go.sum`, not vendored in git; Go version pinned in `deps.lock`), `CGO_ENABLED=0`, reproducible build with `tools/assistant/build.sh`) that does what `./akam` does for a camera already running Akam: `status`, `cameras`, `rename-camera`, `register`, `find-camera` (port probe; opt-in name lookup, ONVIF WS-Discovery and local /24 scan), `led`, `audio`, `picture`, `debug`, `onvif`, `rtsp-auth`, `hostname`, `talk` and `say` (RTSP Digest client, ONVIF audio backchannel, G.711 and WAV in Go; `ffmpeg`/`arecord` only for the microphone and non-WAV files), `doctor`, `self-test`, `version`, `forget-host-key`. Built-in SSH client (`x/crypto/ssh`, the `~/.ssh/akam` key of the wizard, ed25519 host key pinned in `<state dir>/known_hosts`: first contact asks one yes/no defaulting to No, a changed key is a hard error). Same state files and camera layout as the bash wizard (round trip tested in both directions), same texts (golden tests against the bash output), same camera helpers and the same loopback 8091 lines (through an SSH forward). Full-screen bubbletea menu and widgets on a terminal, plain mode otherwise. Backup, image, flash, update, restore and the SD steps stay in bash until phases P2 and P3. `AKAM_USE_BIN=1 ./akam ARGS` hands over to the binary (`$AKAM_BIN` or `tools/assistant/bin/akam`); `./akam help` mentions it. Tests: `tests/assistant_test.sh` (go vet, `go test ./...` with an in-process fake camera that runs the real helper scripts and a fake RTSP server, reproducible build, size budget, bridge). Not yet checked on a real camera.
- **`./akam onvif [enable [PORT] | disable | status]`** (specs/07 step 3, T21, tooling side; the firmware side that listens on 80 and UDP 3702 lands in the same release, an image without it ignores the flag). ONVIF is **off by default**. New camera helper `akam_onvif.sh` (installed in the image like `akam_debug.sh`) keeps the flag `/etc/config/akam/onvif` (`enabled=1|0`, `port=1..65535`, LF, mode 0600, directory 0700, atomic write; absent file = off) and then sends `ak_rtsp ctl ONVIF reload` (an older `ak_rtsp` that answers `ERR unknown command` gets "reboot to apply"); `enable` refuses unless the clear-text credentials file written by `./akam rtsp-auth set` is valid and says how to fix it; `status` also shows `GET onvif.state` when the firmware answers. The wizard asks one yes/no (default No) before `enable`; `disable` and `status` never ask. The `verify` step now ends with "Make the camera visible to ONVIF apps (NVRs, ONVIF Device Manager)? [y/N]" (default No, no terminal = No, shown in `--dry-run`) and offers `rtsp-auth set` first when no password is set. **Port checks follow the flag:** `verify` and `akam_hwcheck.sh` accept 80/tcp (or the chosen port) and 3702/udp only when ONVIF is on and fail when 80 is open while it is off (it was a warning); otherwise still exactly 22, 554 and 8091. README, install guide (port table, flag file format) and troubleshooting ("an ONVIF app does not find the camera") updated. Tests: `tests/akam_onvif_test.sh`, `tests/wizard_onvif_test.sh`, plus the verify, hwcheck, kit and build_firmware tests.
- **Robustness P0 (specs/10 G01 to G04)**: a software stall watchdog in `ak_rtsp` (`swdog.[ch]`: exit code 70 when the encoder produces no frame for 30 s, or the main loop, AE tick or control accept loop is silent for 60 s; a stalled client or a session that has not issued PLAY never counts; the hardware watchdog is untouched); the stdout tee can no longer block any thread (non-blocking pipe and a private non-blocking console descriptor, lost lines counted in the new `GET log.dropped`); `ak_rtsp_wrapper.sh` waits 0, 2, 5, 10 then 30 s between starts after short runs, keeps a crash counter in `/tmp/akam_respawn` and logs every exit to `/tmp/akam_wrapper.log` and syslog; new `akam_net.sh` Wi-Fi supervisor (wpa_supplicant, udhcpc and IPv4 checked every 30 s, repaired with growing delays, does nothing without `/etc/config/wpa_supplicant.conf`); the build slows the stock `drop_caches.sh` loop from 5 s to 60 s. Tests: `tests/swdog_test.sh`, `tests/akam_net_test.sh`, `tests/wrapper_backoff_test.sh`, `tests/control_test.sh` (second run with a stalled stdout), `tests/build_firmware_test.sh`. Not yet checked on hardware (`kill -STOP` cannot be caught from inside the process).
- **ONVIF Device service and authentication gate** (specs/07 step 3, T18; nothing starts it yet, the enable flag and `./akam onvif` come later). `onvif.[ch]` registers the services on the built-in HTTP server and applies the access classes of spec 3.3: the pre-auth list is open; with the RTSP password on, a valid WS-Security UsernameToken (failure: Sender fault `ter:NotAuthorized`, HTTP 400) or a valid HTTP Digest (checked uri, nonces issued by us in a bounded table, increasing `nc`; failure: 401 with a fresh challenge) is required; with it off, reads are open and `SystemReboot`, `SetSystemDateAndTime`, `SetHostname`, `SetNTP` are refused; an invalid password file refuses everything protected. The limiter delay of failed logins no longer sleeps: `http_resp_defer` holds the answer without blocking the poll loop. `onvif_device.[ch]`: GetDeviceInformation, GetCapabilities, GetServices, GetServiceCapabilities, GetSystemDateAndTime, SetSystemDateAndTime (Manual only), GetHostname, SetHostname (the same file as `akam_hostname.sh`; applies at the next power cycle), GetNetworkInterfaces, GetScopes, GetNTP, GetDNS, GetUsers, SystemReboot (reply, then `sync` and `reboot(RB_AUTOBOOT)` 1 s later; the stock watchdog is never touched; the docs call the software reboot unreliable on this hardware, to be checked in H6). Stable device UUID (version 5 style, from the wlan0 MAC). Fixes from the review: `rtsp_auth.c` and `cred.c` are now thread safe (one mutex each, initialised from `main` before any thread), `cred_get_user` copies into a caller buffer, the WS-Security replay cache keeps 128 nonces until their token can no longer pass the Created check and refuses new requests when full instead of evicting a live nonce, and `akam_rtsp_auth.sh` removes its staged files on exit or signal and moves the htdigest file first (a failure of the second move removes the stale plain copy so ONVIF fails closed). Tests: `tests/onvif_test.sh` (real HTTP, golden responses in `tests/fixtures/onvif/`, UUID re-derived independently), `tests/auth_thread_test.sh` (ThreadSanitizer), `tests/http_srv_test.sh`, `tests/cred_test.sh`, `tests/rtsp_auth_cmd_test.sh`. Not yet checked on hardware.
- **ONVIF groundwork: credential store and crypto primitives** (specs/07 step 3, T15; nothing listens yet). Own MIT `sha1.[ch]` (FIPS 180-1 vectors incl. one million `a`) and `b64.[ch]` (RFC 4648, strict decode with bounds). `cred.[ch]` reads `/etc/config/akam/credentials` (`user=` and `pass=` lines, mode 0600 or the file is refused, reloaded when it changes, checked every 3 s at most) and checks a WS-Security UsernameToken PasswordDigest (`Base64(SHA1(nonce + created + password))`, constant-time, 32-nonce replay cache, `Created` within +/- 5 min only when the camera clock is 2024 or later). The HTTP Digest check of `rtsp_auth.c` is exposed (`rtsp_auth_digest_verify`) and the RTSP failure limiter is shared (`rtsp_auth_note_failure`), so ONVIF failures and RTSP failures slow each other down. **`./akam rtsp-auth set` now also stores the password in clear text on the camera** (`/etc/config/akam/credentials`, mode 0600, directory 0700, atomic, user decision U2) next to the Digest hash, and the wizard says so; it goes over SSH on stdin to the new `akam_rtsp_auth.sh set-creds`, never in a command line. `disable` removes both files; `status` shows `ONVIF-ready`; the legacy `set-hash` removes the stale copy. Passwords are now limited to 8 to 128 printable characters. Tests: `tests/sha1_test.sh`, `tests/cred_test.sh`, `tests/rtsp_auth_cmd_test.sh`, `tests/wizard_rtsp_auth_test.sh`.
- **`./akam audio` and `./akam picture`** (over SSH, loopback writes on 8091, no confirmation, like `./akam led`). `audio [show | volume 0-100 | beep | on | off | talk on|off]` reads and sets `audio.out_volume`, `audio.out_test`, `audio.out_enable`, `audio.talk_enable` (saved by the camera as before; `on` says when a reboot is needed) and shows `audio.out_state`, underruns and drops. `picture [show | brightness N | contrast N | saturation N | sharpness N | wb conf|manual | night auto|day|night | reset]` reads and sets `isp.*` (-50 to 50), `img.wb` and `night.mode`; `img.wb` (in `/etc/config/akam/image`, the other lines of that file are kept) and `night.mode` (in `/etc/config/akam/night`, mode 0600, removed when back to auto) are saved too, only when the value changes, and applied at start (`night.mode` before the first day/night decision); invalid saved values are ignored. The wizard now accepts a negative number as a value (`./akam picture contrast -20`). **`isp.brightness/contrast/saturation/sharpness` are now saved** in `/etc/config/akam/picture` (mode 0600, atomic write with fsync, only after a SET from the camera itself, so the PC tool over the network never writes flash; removed when all four are 0), and are applied again after every day/night switch and `img.reload`, which resend the calibration and applied once at start after the ISP and AE run; out-of-range or invalid lines are ignored. Tests: `tests/wizard_audio_test.sh`, `tests/wizard_picture_test.sh`, `tests/isp_tune_test.sh`, `tests/isp_effects_test.sh`, `tests/control_test.sh`. The remote `nc <cam> 8091` SET instructions of the audio troubleshooting section are replaced by `./akam audio`. Not yet checked on hardware.
- **8091 integrates the metrics and closes the slot lockout** (specs/07 4.2). `GET <metric>` answers `key=value` for the `ctl_sys` keys (`sys.*`, `net.*`, `video.*`, `rtsp.clients`, `rtsp.auth`) and `GET ctl.clients`; `LIST` now ends with the metric keys, `ctl.clients` and `ctl.debug` (the first lines are unchanged, golden test updated; there is no `STATUS json` yet). A CR or LF in any value (an SSID) becomes `?`, so a reply is always one line. `rtsp.auth` is correct from start-up: the credential state is read once at server start and again every 5 s while no client is connected (one `open()` of a small file; never a secret). One of the 4 client slots is reserved for loopback peers (a remote peer gets at most 3), and an idle remote peer is dropped after 120 s (900 s for loopback and while `DEBUG` is on), so idle LAN connections can no longer lock out the SSH helpers. Every `SET` runs under one mutex (isp.c's unlocked baseline and the ae/night get-modify-set); the reply is sent after the unlock and the LOG pump never takes it. `ak_rtsp ctl` ends at the `.` of a `LIST` or 250 ms after the last line (1 s for the first byte, 3 s at most) instead of always waiting 1 s. README says 8091 takes 4 clients while RTSP stays at one. Tests: `tests/control_test.sh` (metrics via stubs, hostile SSID, slot reservation and idle limits over TCP, alias timing against a slow fake server).
- **Two-way audio: the ONVIF RTSP audio backchannel on port 554** (specs/07 step 1; replaces the unbuilt port 8092 and its HMAC). A client that sends `Require: www.onvif.org/ver20/backchannel` gets the usual SDP plus one send-only PCMU/PCMA 8 kHz track (`streamid=2`), only when the RTSP Digest password is on and audio out and `audio.talk_enable` are on; otherwise `551 Option not supported` (go2rtc then falls back to plain video). A client without the header gets a byte-identical SDP (golden test). Interleaved TCP and UDP RTP in, bounds-checked G.711 decode, jitter buffer, amplifier policy of audio out; a talk session works inside the same connection as video and microphone, or alone (idle drop after 30 s without RTP); one talker at a time. Half duplex: the camera microphone is replaced by silence only while speech plays (energy gate at -45 dBFS RMS, 300 ms hold plus the jitter delay), `audio.talk_duplex=half|full`; G.711 silence no longer switches the amplifier on. New 8091 keys: `audio.talk_enable`, `audio.talk_duplex` (saved), read-only `audio.talk_state/codec/packets/dropped/lost/sessions/mic_muted` and `audio.out_underruns/drops/buf_ms`. New host client `tools/akam-talk` (C, MIT, built with the C compiler or the pinned Zig for Linux, macOS and Windows: `tools/akam-talk/build.sh --cross`) and wizard commands `./akam talk [SECONDS | test]` and `./akam say FILE` (the password goes through the environment only). A PLAY with nothing SETUP is now answered 455 instead of crashing the loop. Stripped `ak_rtsp` +13 KB. Tests: `rtp_in`, `audio_vad`, `talk`, `rtsp_sdp`, `rtsp_idle`, `audio_out`, `akam_talk`, `wizard_talk`, and `rtsp_backchannel_test.sh` (the real `rtsp.c` loop over loopback TCP and UDP with a fake speaker and microphone). Not yet checked on a camera; see `docs/two_way_audio.md` (configuration for go2rtc, Frigate and Home Assistant, the one-client limit, hardware check list).
- Front LED and IR LED settings, saved on the camera (`/etc/config/akam/leds`) and applied at start-up. New 8091 keys `led.status` (`on` default, `off`, `auto`), read-only `led.state` and `night.ir_led` (`auto` default, `off`). `auto` blinks the front LED while the camera starts or has no Wi-Fi (IPv4 address on `wlan0`), blinks slowly while an RTSP client is playing (privacy indicator) and stays solid otherwise; a single thread wakes twice a second, never blocks the RTSP loop, and a sysfs failure is logged once. `night.ir_led=off` keeps the IR-cut filter and night image switching but never lights the IR LEDs (GPIO 70). Defaults leave the behaviour unchanged. New wizard command `./akam led [show | status on|off|auto] [ir auto|off]` (over SSH, no confirmation). Tests: `tests/leds_test.sh`, `tests/wizard_led_test.sh`. See `specs/06-spec-leds.md`; not yet checked on hardware.

### Changed

- Day / night switch reworked (specs/08 sections 3.4 and 11): the camera was in NIGHT mode in a lit room because `night.c` switched as soon as the exposure passed 3000 (18 % of its range). Now, like the stock firmware, it goes to night only when the AE is saturated (exposure at 95 % of 16384 and exposure x ISP gain at 95 % of the maximum the AE itself is allowed, read from the exposure block at run time) for 3 s. The return to day is robust to the IR feedback loop (the IR LEDs light the scene): after a minimum night dwell the IR LEDs are switched off for 2 to 3 s (probe) and the AE is read in the ambient light; a lamp switched on at night triggers a probe at once; probes back off when they fail; the dwell doubles after a flap; `night.ir_led=off` reads the exposure directly. The decision is a pure state machine (`night_logic.[ch]`, host test `tests/night_logic_test.sh` with simulated lit room, dusk, dark, IR lit scene and lamp traces). New 8091 keys `night.gain_pct`, `night.day_confirm_samples`, `night.min_night_ms`, `night.probe_ms`, `night.probe_settle_ms`, read-only `night.ae` and `night.logic`; defaults of `night.trigger_hw_exp` (15500), `night.day_hw_exp` (2048) and `night.confirm_samples` (30) changed. Every switch is logged with the values that triggered it. Checked on hardware (akam-01): stays in colour in a lit room, night 3 s after the lens is covered, back to day at the first probe, which runs as soon as the 2 min minimum night is over.
- `img.wb=conf` is now the default (the file's WB block gives better colours, user decision); `wb=manual` stays selectable and is re-applied after every night to day reload. `venc_rc` stays `legacy`.
- Wizard confirmations: the typed phrases (`ERASE <device>`, `YES`, `I UNDERSTAND THIS IS UNTESTED`, `USE UNSIGNED KIT`) are replaced by ONE yes/no (default No, Esc/`q`/Enter = No, refused without a terminal) in a red box that states what will happen; after the yes the wizard answers the downstream prompts itself (`sd_card.sh --yes-i-confirmed <device>`, accepted only with the same `--device`; `YES` to `install_with_flash_tool.sh`). `sd_card.sh` run by hand still asks the typed phrase.
- `ak_rtsp` frees its single client slot: before PLAY a client is dropped after 20 s without a complete request ("idle before PLAY") or if it needs more than 60 s to reach PLAY; a client that is playing is never dropped for idleness (write stall, disconnect, BYE and TEARDOWN as before). Host test `tests/rtsp_idle_test.sh`.

### Security

- **P2 gaps (specs/10 G15 to G19 and G22)**, host only, not checked on a camera. **G16:** every numeric `SET` of `ae.*`, `night.*` and `isp.*` on port 8091 is parsed strictly and range checked (`ERR <key> range [lo,hi]`, nothing changed), so `night.confirm_samples=0`, a negative `lock_ms` or trailing text can no longer reach the state machine; valid values behave as before. **G17:** stack canaries (`-fstack-protector-strong`) on the parsers of untrusted input only (ONVIF/SOAP/HTTP, RTSP auth, the 8091 line parser): +1.06 % stripped size (322,924 to 326,356 bytes) against +3.1 % for all files; `-Wformat-security` added; `_FORTIFY_SOURCE`, RELRO and PIE do not apply to this static musl build. Boot test on hardware pending. **G18:** `--no-isp-init` removed and the `main.c` header refreshed; the rest of the legacy list is kept and itemised in specs/10. **G19:** the backup folder is created private (0700, files 0600, also for imports and copies) with a secrets warning. **G15:** the unsigned SD update path and its maintenance-flag guard are documented (README, lockdown guide). **G22:** investigated, hardware experiment proposed, no change. G20 and G21 are deferred. Tests: `tests/control_test.sh`, `tests/wizard_camera_test.sh`.
- **Port 8091 is read-only from the network** (specs/07 step 4, T24 and T26). `SET`, `SAVE` and `RESET` from a peer that is not on the camera itself (not 127.0.0.0/8) answer `ERR read-only mode, see akam_debug.sh`; reads (`LIST`, `GET`) are unchanged byte for byte (golden test). Writes from the camera (the SSH helpers, `./akam led`) always work. New command `DEBUG on [minutes] | off | status` (loopback only, ERR from the network): a RAM-only flag, off at every start and reboot, default 60 minutes, 1 to 1440, expiry on the monotonic clock (the camera clock is at 2000 without NTP); readable as `GET ctl.debug` and `GET ctl.debug_remaining`. The control server now serves up to 4 clients at once (a small thread each, 64 KB stack; a fifth gets `ERR busy`; a client silent for 15 minutes is dropped) instead of replacing the previous one, and LOG lines go to every client without ever blocking (`MSG_DONTWAIT`, dropped when the socket is full). New multi-call alias `ak_rtsp ctl <line>` (handled before any hardware init). New camera helper `akam_debug.sh` and wizard command `./akam debug [on [MINUTES] | off | status]`; `akam_hwcheck.sh` prints a `debug:` line; the PC tuning tool says to run `./akam debug on` when it gets `ERR read-only`; README, install guide, troubleshooting (audio step A), test plan and tuning doc rewritten. Stripped `ak_rtsp` +4.8 KB. Tests: `tests/control_test.sh` (the real `control.c` over TCP with stub modules: gating, DEBUG, slots, golden reads, LOG flood, `ak_rtsp ctl`), `tests/akam_debug_test.sh`, `tests/wizard_debug_test.sh`. Not yet checked on hardware.
- Optional RTSP password (Digest login, RFC 2617 MD5 without `qop` for VLC/live555, ffmpeg, go2rtc and Frigate), **off by default**. `ak_rtsp` reads `/etc/config/akam/rtsp_auth` (`user:akam:HA1`, never the password) at every protected request: absent = open stream as before, valid = Digest required on everything but `OPTIONS`, damaged = everything refused. Per-connection random nonces, constant-time comparison, delays and a connection limit on failed attempts, no secret in the journal, no restart needed. New camera command `akam_rtsp_auth.sh` (`set`, `set-hash`, `show`, `status`, `disable`), `./akam rtsp-auth [set|disable|status]` (the password is typed and hashed on the PC; only the hash goes over SSH) and an opt-in question at the end of `verify` (default: No); `akam_hwcheck.sh` reports whether it is on. Never managed through port 8091. See `specs/03-spec-rtsp-auth.md`.

### Fixed

- **Firmware review batch F2 (host-tested, not yet checked on hardware).** RTSP: a client that closes and reconnects at once is served (the busy path no longer accepts the newcomer in the round that ends the session and closes it in silence; a newcomer still waiting at the end of a session now gets its `503`); port 8091: `strtok` replaced by `strtok_r` (up to 4 client threads shared one parser state), an `accept()` error such as `EMFILE` no longer ends the server for good, the listener is non-blocking, and a remote peer without DEBUG is cut after one hour even if it trickles bytes (`CTL_SESSION_REMOTE_S`); watchdog: `alarm(120)` from the start of `main` until `swdog_start()` takes over, so a respawn that hangs in a driver call is ended by the kernel and the wrapper restarts it; saved settings (`video.*_cfg`, `isp.*`) are written to flash only when the value changes, and a malformed `video` file is logged once per `LIST` instead of four times; `ak_rtsp_wrapper.sh` no longer counts a stop by SIGTERM or SIGINT (the wizard's restart) as a crash for the backoff; `akam_ntp.sh` stops its `ntpd -q` and `sleep` children on TERM instead of leaving them behind; `akam_hwcheck.sh` reads command lines with `strings`+`paste`, else `tr`, else `comm`, and FAILs instead of passing when no process could be read; the README ONVIF port list now names the refused ports (21 to 24, 554, 8091). Log volume: the per-second `[ae] window` line and the per-frame and `vclock` lines are written only while the 8091 DEBUG mode is on; otherwise one AE summary per minute (and a HUNTING window at most every 10 s). Tests: new close-then-reconnect cases and a less timing-sensitive `rtsp_backchannel_test`, `ae_log_test.sh`, plus swdog, control, video, isp_tune, wrapper_backoff, akam_ntp and hwcheck cases. Stripped `ak_rtsp` +1.4 KB.
- **ONVIF stack review fixes (batch F1, host-tested only)**: the WS-Security replay table no longer refuses correct passwords after 128 logins in 5 minutes (1024 slots of 12 bytes; when full the oldest Created is evicted and a floor refuses anything not newer, and a full table is never counted as a login failure); with the clock unset the first authenticated token anchors a token clock so a captured token cannot be replayed later, and after a clock step the old time base stays valid for 10 minutes. Failed logins now lock the client address out (3 free failures, then 1 to 16 s, per IP, 8 tracked) without evaluating its credentials, so a correct password is no oracle and reconnecting does not help; other clients are unaffected. HTTP Digest nonces are stateless (no table to churn with unauthenticated requests) and an out-of-order `nc` on parallel connections is `stale=true` with no penalty. The HTTP server closes the longest-idle connection when all 4 slots are taken, and a connection that never sent a request gets the 5 s request deadline instead of 30 s. Unknown operations and `GetSnapshotUri` are now a Receiver fault `ter:Action`/`ter:ActionNotSupported` (HTTP 500). For ONVIF Device Manager: Imaging `GetMoveOptions`/`GetStatus` (empty, schema valid; `Move`/`Stop` a clear fault), Device `GetNetworkProtocols`, `GetNetworkDefaultGateway`, `GetDiscoveryMode`, `GetZeroConfiguration`, `GetServices` with `IncludeCapability`, NTP servers of `akam_ntp.sh` in `GetNTP` and `DateTimeType`; capabilities corrected (`RTP_TCP` false, `DiscoveryResolve` true). Fewer flash writes: `SetHostname` with the stored name writes nothing, `ForcePersistence` writes at most once per 2 s (the rest is debounced). The htdigest file is no longer opened on every request (stat signature). WS-Discovery `InstanceId` is a persisted boot counter (`/etc/config/akam/wsd_instance`, one tiny write per start of the responder) and the multicast membership is dropped and re-added every 5 minutes for IGMP snooping switches. `rtsp_in`, `rtsp_busy`, `rtp_in` and `ctl_gate` get stack protectors. Tests: `cred_test` (also built with an 8-slot cache), `onvif_test`, `onvif_media_test`, `http_srv_test`, `rtsp_auth_test`, `wsd_test` (deterministic limiter test, no timing-dependent bound).

Tests in `tests/stock_capture_script_test.sh` (also run once with the camera's BusyBox 1.30.1 under `qemu-arm`); `run --detach` has not been run on a camera yet, the same thing done by hand with `busybox setsid` ran to the end (`rc=0`).

### Release kit

- `tools/release/{make_kit,sign_kit,verify_kit}.sh`: build, sign (`ssh-keygen -Y`) and verify the
  prebuilt-binaries kit (`akam-kit-<version>.tar.xz`, Akam's own files only, never a firmware image);
  see `docs/akam_v1_kit.md`.
- The kit ships `supported_hardware.txt` (validated: LSC 3215672.3 / SI D26228 with its stock APP fingerprint; untested: 3215672.2 and anything else), hashed in `MANIFEST.txt`.

- `src/ak_rtsp/build_firmware.sh --kit DIR|TARBALL` assembles the image from a verified kit (no compiler); source and kit modes install the Akam files from the same `tools/release/image_files.txt`. The image follows the stock APP compression (xz or gzip, block size, BCJ) read from the dump, `--comp` overrides it with a loud warning, other compressors are refused. The dump is compared with `supported_hardware.txt`: anything but `validated` is refused without `--i-understand-untested`, another MTD layout always. Verdicts and fingerprints go to `build_report.txt`. `tools/image/assemble_from_kit.sh` wraps it for a backup directory. A kit directory (no signature to check) needs `--allow-unsigned` like an unsigned tarball; a release kit's time64 gate is replayed on the installed binaries when gdb is present; a kit carrying overlay files this script does not install is refused; the backup must hold `mtdblock0..7.bin` and a readable uImage kernel for a `validated` verdict.

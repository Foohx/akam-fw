# Changelog

## 0.1.0 (unreleased)

First public release. The project was renamed from Camyn to Akam.

### Added

- **Choose your firmware (Go assistant only; host-tested, never run on a real camera).** "Set up a new camera" and "Update this camera" now ask **Which firmware?**: `Akam X.Y.Z (latest)` (the default) and older releases published on GitHub, a kit already downloaded, a kit file, an image file you built (`.squashfs`, exactly 5 242 880 bytes, md5 shown, you take responsibility, default No), and, in the update of an Akam camera with a verified stock backup, "Stock firmware (from your backup)", which is the restore flow with all its gates (marked never tested on a real camera). The release list (`GET api.github.com/repos/Foohx/akam-fw/releases?per_page=30` through the bounded HTTPS client, at most 1 MiB, asked once per session; drafts, prereleases, tags that are not `vX.Y.Z` and releases without the kit, `SHA256SUMS` and `SHA256SUMS.sig` are dropped) is advice only: a chosen kit is still verified by SHA256SUMS and signature exactly as `get-kit` does. Offline, rate limit or a bad answer give a clear message and keep the local choices. Going to a version older than the camera's asks one yes/no (default No). New commands and options: `akam releases [--include-prereleases]`, `akam update --version X.Y.Z | --kit FILE | --image FILE | --stock` (a firmware named on the command line skips the list; `update --kit` and `--version` now really use that kit and build the image from it). `./akam status` shows `Firmware source:` (`release:X.Y.Z`, `kit:PATH`, `image:PATH`, `stock`), recorded after the camera was written and read back. The bash wizard keeps its options and has none of this. A kit is always verified again (a recorded kit of the same version is never reused) and swapped all or nothing: if its image cannot be built here or a downgrade is refused, the previous kit, kit state and image come back untouched; when no builder is available and an image built from your backup is ready, that image is the default row. The camera's Akam version is read over SSH from the manifest the image carries (`/usr/local/akam/MANIFEST.txt`); the version recorded after a write is only a fallback and is dropped when the camera reports another build; `status` records facts (`image:PATH` for an imported image, never `release:`). The bash `update` refuses `--version` and `--kit` (exit 2). Tests: release-list parsing, chooser, downgrade, local kit and image checks, stock gates, the full-screen list, kit rollback, race tests.
- **Video frame rate 20 and 25 fps (`./akam video fps 20|25`, 8091 `SET video.fps_cfg`, assistant options screen; day frame time VTS = 34260 / fps: 10 -> 3426, 15 -> 2284, 20 -> 1713, 25 -> 1370).** Checked in a RAM test on a real camera (nothing flashed): exactly 15.0, 20.0 and 25.0 fps over RTSP (451, 601 and 751 frames in 30 s), no encoder error, low CPU, daylight picture at 20 and 25 fps identical to 15. 30 fps was tested and is not allowed: the picture was dark, grainy and nearly grey. Higher rates shorten the longest exposure (one frame time), so in dim light the picture is darker and grainier and night mode starts earlier; with a bitrate cap each frame gets fewer bits (raise the cap if the Wi-Fi allows it); night mode always runs at 10 fps. The default stays 15 fps. The GOP, the ONVIF frame rate and the SDP follow the configured rate. Host-tested; the full image has not been flashed yet.
- **Kernel log filter (`ak_rtsp klog`, `klog.[ch]`, `klog_run.c`; needs hardware validation).** The vendor LED driver prints a line on every LED write (about 60 a minute while it blinks) and the encoder driver prints bursts of identical errors under network stress, so the 3 x 200 KB syslog files rotated every ~5 minutes. The build now replaces `klogd -n &` in the stock `sbin/main.sh` with `{ /usr/bin/ak_rtsp klog || klogd -n; } &` (`build_firmware.sh` and the assistant's image builder, checked equal to each other): the filter reads `/proc/kmsg`, drops `gpio_led_set` lines, forwards everything else to `/dev/log` as `kern.<level>` with the original priority, and collapses a message that repeats (after removing the `[N]` counter and folding digits, so pids and error codes do not defeat it) into the first line plus one `message repeated N times in the last 60s` summary per message and minute. Idle cost is one blocked `poll()`; it survives a missing or restarted syslogd and is restarted by the `main.sh` line (2 s, 4 s, ... up to 5 times) when a signal kills it; the stock `klogd` runs only when it cannot start (for example `/proc/kmsg` unreadable) or after the fifth crash. A line over 1000 bytes is cut and its tail discarded; after a syslogd restart the first line is resent on a fresh connection. It shows as `akam_klog` in `ps`, so `akam_lockdown.sh` and the `ak_rtsp` checks of `akam_hwcheck.sh` (which now reports it) ignore it. No change to the RAM budget (same syslogd flags). The status LED already skipped writes of an unchanged level (now covered by a test); the 1 Hz and 0.5 Hz blink needs one write per toggle. `drop_caches` already runs every 60 s and is collapsed by the filter. Tests: `tests/klog_test.sh`, `tests/leds_test.sh`, `tests/hwcheck_test.sh`.
- **RTSP/TCP backpressure (`tx_pace.[ch]`; needs hardware validation).** On a weak Wi-Fi link a blocking frame write kept the encoder's stream buffer unreleased until the driver overflowed, re-encoded at maximum QP and lost frames (about 30% at RSSI -78 dBm). `send_video_frame()` now reads the unsent bytes of the client socket (`SIOCOUTQ`) before each frame; above `max(64 KiB, 0.5 s of the configured bitrate)` plus the size of the last keyframe it drops frames (they are released to the encoder at once, so the encoder is drained at the sensor rate whatever the client does) until a keyframe arrives while the backlog is under a quarter of that base, then resumes, so a P-frame is never sent after a dropped frame without a keyframe in between. The watermarks stay inside the real send buffer: the RTSP socket asks for `SO_SNDBUF` 256 KiB (the kernel clamps to `wmem_max` and doubles it; this also turns autotuning off) and each frame reads the size back, cap = 3/4 of it; a frame that would not fit makes the stream enter skip mode, but a keyframe at a backlog under the low mark is always sent. While skipping, a backlog that reaches no new minimum for 15 s (dead peer) or a skip run longer than max(3 GOPs, 10 s) ends the session so the single client slot is freed. The pacing state is reset on PLAY. Audio periods are dropped too while skipping. Known the keyframe-larger-than-the-send-buffer follow-up is done in the next entry. UDP transport and the software watchdog are unchanged. New read-only metric `rtsp.skipped_frames` on 8091 (cumulative); one log line on entering and one on leaving, at most one pair per 10 s. Tests: `tests/tx_pace_test.sh`, `tests/ctl_sys_test.sh`.
- **Optional MQTT client with Home Assistant discovery, `./akam mqtt` (specs/07 step 2; host-tested only, needs hardware validation).** Off by default: with no broker configured `ak_rtsp` creates no thread and no socket for it. `mqtt.[ch]` is a minimal MQTT 3.1.1 codec (own code, no library), `mqtt_ha.[ch]` holds the entity table, the retained discovery documents and the command allow-list, `mqtt_svc.[ch]` the settings files and the one thread (outbound plain TCP only, keepalive and PINGRESP check, last will `offline`, reconnect with a backoff of 5 s doubling to 60 s, fixed buffers, packets too large for the receive buffer are skipped, lower priority than the video threads). One Home Assistant device (MAC-based identifiers) with the status LED, IR LEDs, day/night mode, speaker volume, talk switch, beep button, the four picture sliders and sensors (Wi-Fi signal, uptime, CPU, free memory, temperature when the camera has it, frame rate, bitrate, viewers, day/night state, clock set). Only that list can be commanded (no reboot, no network, hostname or password setting); every payload is validated, retained commands are ignored, the volume and picture sliders stay in RAM. `/etc/config/akam/mqtt` (settings) and `/etc/config/akam/mqtt_pass` (password, its own 0600 file), written by the new camera helper `akam_mqtt.sh` (`set HOST PORT USER` with the password on stdin, `option`, `disable`, `forget`, `status`, `test`); `ak_rtsp ctl MQTT reload|test` (from the camera only) and `GET mqtt.state|mqtt.stats|mqtt.test` on 8091. Both wizards: `./akam mqtt [status|set|disable|forget|test]` (the password is typed hidden and sent on stdin, `set` asks last "Turn MQTT on? [y/N]" with No as the default) and an entry in the assistant's Camera options > Network screen. `akam_hwcheck.sh` checks that MQTT off means no outbound TCP connection of `ak_rtsp` and MQTT on exactly one. Cost: +39 KB stripped `ak_rtsp` (+23 KB with `make EXTRA_CFLAGS=-DMQTT_NO_DNS`, broker then by IPv4 address only), +3 KB bss. Name lookups run in a detached helper so a stop or reload never waits for DNS; saved changes (LED, IR, night mode, talk) are limited to one per 10 s (extra ones are rejected and the real value is republished); a lone `-` is refused as a user name. No TLS yet (separate step 2b). See [MQTT and Home Assistant](docs/mqtt.md).

- **Native assistant: audio without external programs on Linux and Windows (needs hardware validation).** `akam say` decodes MP3 (go-mp3, Apache-2.0), FLAC (mewkiz/flac, Unlicense) and Ogg Vorbis (jfreymuth/oggvorbis, MIT) in pure Go, found by magic bytes and resampled to the 8 kHz mono pipeline (a streaming resampler with an 8th-order 3.6 kHz low-pass against aliasing; files over 30 minutes are refused; damaged files give an error, never a crash). `akam talk` records the microphone with a built-in PulseAudio protocol client (jfreymuth/pulse, MIT; works with PipeWire) on Linux and with direct WASAPI COM calls (shared mode, no cgo, no extra module) on Windows. Microphone order: `AKAM_TALK_CAPTURE_CMD`, built-in backend, ffmpeg, arecord; macOS keeps ffmpeg. `akam doctor` prints an `Audio:` line and lists ffmpeg/arecord only as optional fallbacks. Binary size grows by about 0.25 to 0.35 MiB per target (all still under the 12 MiB budget). New licences listed in `THIRD_PARTY_NOTICES.md` and `akam licenses`.
- **ONVIF hardware follow-ups.** New `tools/hw_tests/onvif_check.py` (Python 3 standard library, `python3 -I`): the check used on the first real-camera ONVIF test, with an unauthenticated HTTP 401 with an empty body treated as the expected refusal, WS-Discovery `XAddrs` parsed as XML, `--rtsp` (Digest DESCRIBE, 200 and an H264 line), `--yes-imaging` / `--no-imaging`, and a note suggesting `./akam ntp set` when the camera clock is not set; host test `tests/onvif_check_test.sh` against a fake ONVIF and RTSP server on 127.0.0.1. Port 8091 now answers `GET fw.version` and `GET sys.hostname` (also in `LIST`, readable from the network, no login; `ssid` and `mac` stay hidden), the keys the assistant discovery relies on. The ONVIF interface probe and MAC lookup are cached (fewer sockets per request). Tests: `control_test.sh`, `onvif_check_test.sh`.

- **P1 gaps (specs/10 G05 to G10 and G14)**, all checked on the host only, none on a camera yet:
  **port 8091 privacy (G05):** `LOG` lines go only to the camera itself or while debug mode is on, and `net.ssid` and `net.mac` read as `hidden` for other machines unless debug mode is on (`net.ip` stays readable). **A second RTSP client (G06)** is answered at once with `503 Service Unavailable` (`CSeq` echoed, `Retry-After: 10`) and closed, instead of waiting in the accept queue for the first viewer to leave; the first client and the video timing are not touched (`rtsp_busy.[ch]`, polled from the session loop, no extra thread); several viewers: restream with go2rtc. **Audio (G07):** the capture is supervised, after 5 read errors it is closed and reopened after 1, 2, 4 ... 60 s instead of stopping for good, and a failed open at start is retried; new persistent key `audio.mic_enable` and `./akam audio mic on|off`: off never opens the microphone and the stream has no audio track at all (needs a reboot to apply). **Time (G08), opt-in:** `./akam ntp [status | set SERVER... | off]` (1 to 3 validated servers in `/etc/config/akam/ntp`, camera helper `akam_ntp.sh` started by the wrapper only when that file exists, one-shot BusyBox `ntpd -q` at low priority, retried until the clock is 2024 or later, then every 6 h; default off, no traffic) and the metric `sys.time_set` on 8091. **RAM logs (G09):** every `/tmp/akam_*.log` is capped (100 lines or 64 KiB, trimmed in place, also the one Dropbear fills). **Wakeups (G10):** microphone off removes about 62 wakeups per second; the 20 ms drain poll and the audio on-demand ideas are documented in specs/10 as needing hardware measurements (they would touch the capture clock and the amplifier), and `akam_hwcheck.sh` prints the measured `wakeups N/s`. **`akam_hwcheck.sh` (G14)** audits UDP listeners (68, 3702 with ONVIF on, ephemeral client ports; anything else FAIL) and every running process against an allow-list (`msgserver` and `cmdserver` are WARN "vendor daemon, review"). Tests: `tests/native/rtsp_busy_test.c`, `audio_sup_test.c`, `tests/akam_ntp_test.sh`, `wizard_ntp_test.sh`, and the control, ctl_sys, audio_out, rtsp_sdp, rtsp_backchannel, wizard_audio, lockdown and hwcheck tests. - **Saved video settings, `./akam video` (specs/10 G11, items 1 and 3; needs hardware validation)**. `/etc/config/akam/video` (mode 0600, atomic, removed when everything is default) holds `bitrate=` (500 to 3000 kbit/s, the VBR+ ceiling, default 1536), `fps=` (10 or 15, default 15) and `gop=` (key frame interval in seconds, 1 to 4, default 2, sent to the encoder as seconds times fps frames). Read once at start (`video_cfg.[ch]`, before the ISP frame rate is set), used for the encoder (`venc.c`), the sensor frame rate and VTS (`ae.c`, and `night.c` for the day side: 15 fps / VTS 2284 or 10 fps / VTS 3426, the two pairs the code already sent), the capture clock, the bitrate window and the IDR wait (`rtsp.c`), and the ONVIF Media reports (`GetProfile(s)`, `GetVideoEncoderConfiguration(s)`, its Options, `GetVideoSources`). With no file nothing changes: same encoder parameters and byte-identical ONVIF goldens. 8091 keys `video.bitrate_cfg`, `video.fps_cfg`, `video.gop_cfg` and read-only `video.cfg_pending` (`video_ctl.[ch]`; loopback SET only, a network SET is refused; they do not clash with the measured `video.bitrate` and `video.fps_actual`). `./akam video [show | bitrate N | fps N | gop N]` sets them over SSH, says "applies at the next restart of the video service" and offers (default No) to run `kill the ak_rtsp pid` so the wrapper respawns it. The software watchdog limit (30 s without a frame) is wall-clock, with a compile-time check that it stays at least 100 frame periods at 10 fps. Not offered: resolution (ISP crop, VI formats and the encoder DMA pool exist for 1920x1080 only) and flip/mirror (only the ioctl number is known). Tests: `tests/video_cfg_test.sh`, `tests/wizard_video_test.sh`, `tests/onvif_media_test.sh` (configured values), `tests/control_test.sh`.
- **ONVIF wiring (specs/10 section 1)**: `ak_rtsp` now starts the ONVIF HTTP server and WS-Discovery from the opt-in flag file `/etc/config/akam/onvif` (`onvif_cfg.[ch]`: strict parser, exactly `enabled=` and `port=`, ports 21-24, 554 and 8091 refused, anything invalid or absent = off with one log line). Started after the video and the RTSP listener are up, so it never delays them; stopped on the error path. `ak_rtsp ctl ONVIF reload` (loopback only) re-reads the file and starts, stops or moves the services at run time without touching the video and answers `OK onvif.state=<state>`; `GET onvif.state` (and `LIST`) says `off`, `on:<port>`, `no_password` (enabled, password on, no valid clear-text credentials: nothing started) or `error:<reason>` (`port_in_use` ...). With the RTSP password OFF the service starts (reads open, writes refused, spec 3.3). Off: no thread, no socket. On: two threads, the HTTP poll has no timeout when idle and WS-Discovery ticks every 30 s. Device scopes (Profile Streaming and S, name from the hostname, hardware AK3918AV130, location) are rebuilt at each reload; XAddrs are computed per client. `arm_atomics.S` gains `__sync_lock_test_and_set_4` (needed once `http_srv.c` is linked). Tests: `tests/onvif_svc_test.sh` (parser, state machine, port in use, end-to-end GetSystemDateAndTime/GetDeviceInformation and a WS-Discovery Probe), `tests/control_test.sh` (remote reload refused, `onvif.state`). Not yet checked on hardware.

- **`./akam onvif [enable [PORT] | disable | status]`** (specs/07 step 3, T21, tooling side; the firmware side that listens on 80 and UDP 3702 lands in the same release, an image without it ignores the flag). ONVIF is **off by default**. New camera helper `akam_onvif.sh` (installed in the image like `akam_debug.sh`) keeps the flag `/etc/config/akam/onvif` (`enabled=1|0`, `port=1..65535`, LF, mode 0600, directory 0700, atomic write; absent file = off) and then sends `ak_rtsp ctl ONVIF reload` (an older `ak_rtsp` that answers `ERR unknown command` gets "reboot to apply"); `enable` refuses unless the clear-text credentials file written by `./akam rtsp-auth set` is valid and says how to fix it; `status` also shows `GET onvif.state` when the firmware answers. The wizard asks one yes/no (default No) before `enable`; `disable` and `status` never ask. The `verify` step now ends with "Make the camera visible to ONVIF apps (NVRs, ONVIF Device Manager)? [y/N]" (default No, no terminal = No, shown in `--dry-run`) and offers `rtsp-auth set` first when no password is set. **Port checks follow the flag:** `verify` and `akam_hwcheck.sh` accept 80/tcp (or the chosen port) and 3702/udp only when ONVIF is on and fail when 80 is open while it is off (it was a warning); otherwise still exactly 22, 554 and 8091. - **Robustness P0 (specs/10 G01 to G04)**: a software stall watchdog in `ak_rtsp` (`swdog.[ch]`: exit code 70 when the encoder produces no frame for 30 s, or the main loop, AE tick or control accept loop is silent for 60 s; a stalled client or a session that has not issued PLAY never counts; the hardware watchdog is untouched); the stdout tee can no longer block any thread (non-blocking pipe and a private non-blocking console descriptor, lost lines counted in the new `GET log.dropped`); `ak_rtsp_wrapper.sh` waits 0, 2, 5, 10 then 30 s between starts after short runs, keeps a crash counter in `/tmp/akam_respawn` and logs every exit to `/tmp/akam_wrapper.log` and syslog; new `akam_net.sh` Wi-Fi supervisor (wpa_supplicant, udhcpc and IPv4 checked every 30 s, repaired with growing delays, does nothing without `/etc/config/wpa_supplicant.conf`); the build slows the stock `drop_caches.sh` loop from 5 s to 60 s. Not yet checked on hardware (`kill -STOP` cannot be caught from inside the process).
- **ONVIF Device service and authentication gate** (specs/07 step 3, T18; nothing starts it yet, the enable flag and `./akam onvif` come later). `onvif.[ch]` registers the services on the built-in HTTP server and applies the access classes of spec 3.3: the pre-auth list is open; with the RTSP password on, a valid WS-Security UsernameToken (failure: Sender fault `ter:NotAuthorized`, HTTP 400) or a valid HTTP Digest (checked uri, nonces issued by us in a bounded table, increasing `nc`; failure: 401 with a fresh challenge) is required; with it off, reads are open and `SystemReboot`, `SetSystemDateAndTime`, `SetHostname`, `SetNTP` are refused; an invalid password file refuses everything protected. The limiter delay of failed logins no longer sleeps: `http_resp_defer` holds the answer without blocking the poll loop. `onvif_device.[ch]`: GetDeviceInformation, GetCapabilities, GetServices, GetServiceCapabilities, GetSystemDateAndTime, SetSystemDateAndTime (Manual only), GetHostname, SetHostname (the same file as `akam_hostname.sh`; applies at the next power cycle), GetNetworkInterfaces, GetScopes, GetNTP, GetDNS, GetUsers, SystemReboot (reply, then `sync` and `reboot(RB_AUTOBOOT)` 1 s later; the stock watchdog is never touched; the docs call the software reboot unreliable on this hardware, to be checked in H6). Stable device UUID (version 5 style, from the wlan0 MAC). Fixes from the review: `rtsp_auth.c` and `cred.c` are now thread safe (one mutex each, initialised from `main` before any thread), `cred_get_user` copies into a caller buffer, the WS-Security replay cache keeps 128 nonces until their token can no longer pass the Created check and refuses new requests when full instead of evicting a live nonce, and `akam_rtsp_auth.sh` removes its staged files on exit or signal and moves the htdigest file first (a failure of the second move removes the stale plain copy so ONVIF fails closed). Tests: `tests/onvif_test.sh` (real HTTP, golden responses in `tests/fixtures/onvif/`, UUID re-derived independently), `tests/auth_thread_test.sh` (ThreadSanitizer), `tests/http_srv_test.sh`, `tests/cred_test.sh`, `tests/rtsp_auth_cmd_test.sh`. Not yet checked on hardware.
- **ONVIF groundwork: credential store and crypto primitives** (specs/07 step 3, T15; nothing listens yet). Own MIT `sha1.[ch]` (FIPS 180-1 vectors incl. one million `a`) and `b64.[ch]` (RFC 4648, strict decode with bounds). `cred.[ch]` reads `/etc/config/akam/credentials` (`user=` and `pass=` lines, mode 0600 or the file is refused, reloaded when it changes, checked every 3 s at most) and checks a WS-Security UsernameToken PasswordDigest (`Base64(SHA1(nonce + created + password))`, constant-time, 32-nonce replay cache, `Created` within +/- 5 min only when the camera clock is 2024 or later). ### Fixed

- **Review fixes for the kernel log filter, the RTSP session and the TCP pacing (host-tested; needs hardware validation).** `pidof ak_rtsp` also lists the kernel log filter (same exe, shown as `akam_klog`), so the assistant's and the wizard's video restart now skips it by cmdline, the filter ignores SIGUSR1 and SIGHUP, and the restart loop in `sbin/main.sh` no longer counts a stop request (exit 143/130) or a run longer than 60 s as a crash (five quick crashes in a row still fall back to the stock `klogd`). The filter waits up to 300 ms for room in the syslog socket instead of dropping a burst, never remembers a line it could not deliver, reports `N kernel lines lost (syslogd busy)`, forwards every crit/alert/emerg line and words its summary "since the last report". RTSP: a repeated SETUP of a track releases the old transport and sockets (they leaked until `accept()` failed with EMFILE), SETUP while playing is answered 455, a track on another lower transport than the session's is answered 461, and a UDP RTP socket is no longer closed twice. TCP pacing: the send room is part of `tx_pace_decide()`, so a keyframe that never fits no longer restarts the skip run and the client is dropped after `max_skip_ms`; a keyframe is admitted only at a backlog under the base mark; the dead-peer rule applies only above the low mark; kernel room is counted as zero while the queue holds bytes; a full queue (ENOBUFS) in the middle of a frame skips to the next keyframe, and on audio or RTCP drops that packet, instead of ending the session; nothing more is written once a write failed; TEARDOWN gets a bounded final flush; a connected client that is not playing keeps the encoder ring drained.
- **Deep-review fixes (MQTT, picture settings, audio; host-tested only).** The `isp.*` setters (8091, ONVIF Imaging, MQTT, saved picture at start) now run under the ISP configuration lock: they raced with the day/night pipeline reload that frees the sharpness baseline (crash or heap corruption on a slider flood plus a night-mode switch). MQTT: command limits are token buckets that survive reconnects (every command 5/s with a burst of 10; saved changes burst 4 then one per 30 s; beep one per 2 s; a command equal to the current value is free), `connecting` can no longer overwrite `connected`, the keepalive also pings when nothing was sent for half the interval, the backoff restarts only after a connection that lasted 60 s, a packet of 64 KiB or more is a protocol error, a refused subscription is `error:subscribe`, at most 4 abandoned DNS lookups at once, the node id comes from the MAC only (`error:mac` until it is known) and entities the camera lacks get their retained discovery document cleared, `MQTT reload` answers `ERR` when the start failed. `akam_mqtt.sh`: the new host is written disabled before the password, stale temporary files are removed, the test waits 45 s, and "Applied now" shows the real state. A RAM-only speaker volume is no longer written to flash by the next save of another audio key. The MQTT host test was hardened against load (flake fixes).
- **Assistant: `akam doctor` install hints.** The package name is now chosen per tool and per package manager: `arecord` is in `alsa-utils` (pacman, apt), `mksquashfs` and `unsquashfs` in `squashfs-tools` (pacman, apt) or `squashfs` (brew), `ffmpeg` is `Gyan.FFmpeg` on winget. Where a tool has no package (the squashfs tools on Windows, `arecord` outside Linux) the hint says so and points to `--builder native` (experimental, needs none) or WSL instead of a command that does not work. The stale "until the native builder lands" wording is gone. Table-driven tests for every tool and OS.
- **RTSP/TCP writer without blocking the encoder (`net_tx` queue mode, `tx_pace_no_room`; needs hardware validation).** A keyframe larger than the free kernel send buffer was still written with a blocking `send` loop while its encoder stream buffer was held (between `GET_STREAM` and `RELEASE_STREAM`), so one slow link could starve the encoder. For RTSP/TCP clients `net_tx` now has a per-client queue (256 KiB, allocated once at PLAY; if the allocation fails the client keeps the old blocking writes): bytes the socket does not take at once are appended to it, the client loop drains it on `POLLOUT` (a ring: no memmove, whatever the fill level), and the encoder buffer is released as soon as the frame has been serialised. This is the private copy (already RTP/interleave framed), so the frame is never torn: nothing goes to the socket while the queue is non-empty, and a frame is started only when its wire size fits the free kernel buffer plus the queue (otherwise `tx_pace_no_room()` enters SKIP mode, so a P-frame is still only dropped by entering SKIP mode and the stream resumes at a drained keyframe). Pacing now uses kernel backlog plus queued bytes, with the cap extended by the queue size; a keyframe is therefore sent whole even above the kernel buffer. A queue that takes no byte for 15 s ends the session (same budget as before); a write that overflows the queue fails with `ENOBUFS` and drops the client. UDP is unchanged. The project was called Camyn during early development. Everything user-visible was renamed; the
flash layout, ports, the `ak_rtsp` binary name, the 8091 protocol and the persistent key files under
`/etc/config/dropbear/` are unchanged, so an existing camera keeps its host key and `authorized_keys`
after a reflash.

| Former name | New name |
|---|---|
| `CAMYN_*` environment variables and flags (`CAMYN_ROOT`, `CAMYN_FLASH_I_KNOW`, ...) | `AKAM_*` |
| `camyn_*.sh` scripts (`camyn_ssh.sh`, `camyn_lockdown.sh`, `camyn_hwcheck.sh`, `camyn_reflash_ssh.sh`) | `akam_*.sh` |
| `docs/camyn_v1_*.md`, `specs/*-camyn-v1.md` | `docs/akam_v1_*.md`, `specs/*-akam-v1.md` |
| SD card folder `camyn/` (with `authorized_keys`) | `akam/` |
| SD card flag file `CAMYN_MAINTENANCE` | `AKAM_MAINTENANCE` |
| On the camera: `/usr/local/camyn/`, `/tmp/camyn_*` | `/usr/local/akam/`, `/tmp/akam_*` |
| `LICENSE.camyn` in the image | `LICENSE.akam` |

### Release kit

- `tools/release/{make_kit,sign_kit,verify_kit}.sh`: build, sign (`ssh-keygen -Y`) and verify the
  prebuilt-binaries kit (`akam-kit-<version>.tar.xz`, Akam's own files only, never a firmware image);
  see `docs/akam_v1_kit.md`.
- The kit ships `supported_hardware.txt` (validated: LSC 3215672.3 / SI D26228 with its stock APP fingerprint; untested: 3215672.2 and anything else), hashed in `MANIFEST.txt`.

- `src/ak_rtsp/build_firmware.sh --kit DIR|TARBALL` assembles the image from a verified kit (no compiler); source and kit modes install the Akam files from the same `tools/release/image_files.txt`. The image follows the stock APP compression (xz or gzip, block size, BCJ) read from the dump, `--comp` overrides it with a loud warning, other compressors are refused. The dump is compared with `supported_hardware.txt`: anything but `validated` is refused without `--i-understand-untested`, another MTD layout always. Verdicts and fingerprints go to `build_report.txt`. `tools/image/assemble_from_kit.sh` wraps it for a backup directory. A kit directory (no signature to check) needs `--allow-unsigned` like an unsigned tarball; a release kit's time64 gate is replayed on the installed binaries when gdb is present; a kit carrying overlay files this script does not install is refused; the backup must hold `mtdblock0..7.bin` and a readable uImage kernel for a `validated` verdict.

### Deprecated aliases (removed in the next release)

An SD card prepared before the rename still works with the new image:

- `akam_ssh.sh` reads `camyn/authorized_keys` when `akam/authorized_keys` is absent and logs a
  `DEPRECATED` line in `/tmp/akam_ssh.log`.
- The file `CAMYN_MAINTENANCE` at the card root is accepted as `AKAM_MAINTENANCE` by the patched
  `service.sh` (SD hooks and the RAM marker), by `akam_lockdown.sh` (logs `DEPRECATED`) and by
  `akam_hwcheck.sh` (prints a `WARN`). Build without the alias with `AKAM_MAINT_FLAG_LEGACY=`.
- `flash_guard.sh` accepts `CAMYN_FLASH_I_KNOW=1` as `AKAM_FLASH_I_KNOW=1`, with a warning.
- `patch_service_sh.sh` recognises daemon lines already disabled with the former `CAMYN-DISABLED:` marker.

What to change on your side: rename the `camyn` folder and the `CAMYN_MAINTENANCE` file on your SD
card, use the new script and variable names, and (optionally) rename your local `~/.ssh/camyn` key
and the `~/camyn-backup` / `~/camyn-work` / `~/camyn-sdprep` directories that the docs now call
`~/.ssh/akam`, `~/akam-backup`, `~/akam-work` and `~/akam-sdprep` (`prepare_first_boot_sd.sh` looks for
the toolkit clone in `~/akam-sdprep/toolkit` by default: pass `--toolkit ~/camyn-sdprep/toolkit` to reuse an old clone).

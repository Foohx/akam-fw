# Changelog

## Unreleased: project renamed from Camyn to Akam

- Image quality against the stock firmware (grain), analysis and A/B switches, defaults unchanged: `specs/08-spec-image-quality.md` records what a stock day / night capture shows (the stock sends the 30 ISP blocks of `sensor_isp.conf` unmodified, no run-time per-gain updates, same gain limits; the differences found are the `rc` sub-struct of the encoder, a hand-made WB block, the night trigger and the comparison itself) and a hardware test plan. New 8091 keys `img.wb` (`manual` | `conf`), `img.poll`, `img.reload`, `img.dump` (live ISP blocks against the file, log and `/tmp/isp_live/isp_blocks.bin`) and read-only `img.venc_rc`; start-up options `venc_rc=stock`, `wb=conf`, `poll=1` from the environment (`AKAM_VENC_RC`, ...), `/tmp/akam_image` (RAM) or `/etc/config/akam/image`. `isp_dump --blocks [--all] [--out DIR]` reads the live blocks; new host tools `tools/hw_tests/image_noise.py` (temporal / spatial noise, bit rate) and `tools/hw_tests/isp_block_diff.py` (our blocks against a stock capture). Tests: `isp_blocks_test.sh`, `imgq_test.sh`, `image_noise_test.sh`, `isp_block_diff_test.sh`. Not yet checked on hardware.
- Front LED and IR LED settings, saved on the camera (`/etc/config/akam/leds`) and applied at start-up. New 8091 keys `led.status` (`on` default, `off`, `auto`), read-only `led.state` and `night.ir_led` (`auto` default, `off`). `auto` blinks the front LED while the camera starts or has no Wi-Fi (IPv4 address on `wlan0`), blinks slowly while an RTSP client is playing (privacy indicator) and stays solid otherwise; a single thread wakes twice a second, never blocks the RTSP loop, and a sysfs failure is logged once. `night.ir_led=off` keeps the IR-cut filter and night image switching but never lights the IR LEDs (GPIO 70). Defaults leave the behaviour unchanged. New wizard command `./akam led [show | status on|off|auto] [ir auto|off]` (over SSH, no confirmation). Tests: `tests/leds_test.sh`, `tests/wizard_led_test.sh`. See `specs/06-spec-leds.md`; not yet checked on hardware.
- Developer tool (the audio part ran on a real camera, the camera then rebooted ~15 s after the restart of `anyka_ipc`, cause not established, see `docs/stock_capture.md`): `stock_hook.so` (LD_PRELOAD, raw syscalls) records how the stock `anyka_ipc` drives the speaker, GPIO, PWM / LED / light sensor and ISP to the SD card; `tools/hw_tests/stock_capture.sh` installs it without touching the watchdog or flash and restores everything; `parse_stock_capture.py` summarises a run; `stock_capture_pack.sh` copies the kit to the card. See `docs/stock_capture.md`.
- Stock capture, rework after the first run's reboot: the hook uses about 0.8 KiB of the application's stack instead of up to 1.8 KiB and rate-limits polled ISP blocks; ISP parameter blocks are written in full (real size, up to 46584 bytes) to `isp_blocks.bin`, once per distinct content, and the parser shows which words changed and when, and what differs between the phases of a day/night run; `run --daynight` / `--phase SEC:TEXT` print prompts ("cover the lens now") and record them with typed notes; a per-second heartbeat (`timeline.log`), rolling `dmesg_live.txt`, and logs fsync'd every 2 s (file by file, no global `sync`) survive a reboot; `CHILD` lines show the commands `anyka_ipc` runs with `system()` / `popen()` (a `reboot -f` would be visible; logged by the hook itself because the camera's `sh` is a static BusyBox that ignores `LD_PRELOAD`); `/tmp/camera_start_times` is recorded and reset (RAM only); a run that never finished is reported by the parser and by the next `check` / `run`.
- Documentation clarity pass: the README is now a short three-step quick start (clone, `./akam`, follow the menu) with sections for several cameras, update, hostname, video password and limits; new `docs/README.md` index; the hardware, image quality and methods notes moved to `docs/upstream_background.md` and the repository map to `docs/repository_overview.md`; the manual procedure pages are marked advanced and no longer say "not validated on hardware" where the wizard has since validated the route.
- Wizard fixes from the first run on a real camera: **Wi-Fi is now saved on the camera** (`flash` and `verify` create `/etc/config/wpa_supplicant.conf` from the card's `wifi.conf` ON the camera with `preflight_check.sh --ensure-wifi`, a hard gate: the card is never to be removed while the file is missing; the password never goes through the PC); the **flash is judged by the read-back md5** of `/dev/mtd7` (a real success was reported as a failure because `printf | grep -q` died of SIGPIPE under `pipefail` on 200 KB of progress output); terminal escape codes from BusyBox `ls` are stripped (false "the card does not carry the image" warning); flash_tool's carriage-return progress bars become one progress bar (telnet and SSH routes, `reflash_over_ssh.sh` included); `verify` shows what it waits for with a spinner and elapsed time and explains a timeout (no Wi-Fi saved); the SSH key is chosen among `~/.ssh/*.pub` ed25519 keys when `~/.ssh/akam.pub` is absent and remembered; `ssh -o LogLevel=ERROR` hides the post-quantum warning.
- Wizard cameras: a short **camera name** (`./akam --camera NAME`, asked on the first run, key `c` in the menu, `./akam cameras`, `rename-camera`), one state per camera (progress of earlier versions is one camera you name), the name in the backup and image folders and as the camera's **network name** (`./akam hostname [NAME]`, also after `verify`, through the camera command `akam_hostname.sh` when the firmware has it), and `./akam --camera NAME --ip IP [--backup-dir DIR] register` for a camera that already runs Akam. Entering a step from the menu shows its summary and asks "Start this step? [Y/n]".
- Wizard confirmations: the typed phrases (`ERASE <device>`, `YES`, `I UNDERSTAND THIS IS UNTESTED`, `USE UNSIGNED KIT`) are replaced by ONE yes/no (default No, Esc/`q`/Enter = No, refused without a terminal) in a red box that states what will happen; after the yes the wizard answers the downstream prompts itself (`sd_card.sh --yes-i-confirmed <device>`, accepted only with the same `--device`; `YES` to `install_with_flash_tool.sh`). `sd_card.sh` run by hand still asks the typed phrase.

- Configurable network hostname: the camera now announces `akam-XXXX` (last 4 hex digits of the wlan0 MAC) to the router instead of `IPCamera`. New camera command `akam_hostname.sh` (`set`, `show`, `status`, `reset`, `apply`; RFC 1123 single label, 1 to 32 characters, stored lowercase in `/etc/config/akam/hostname`, atomic write). `ak_rtsp_wrapper.sh` applies it at boot before DHCP, and the build patches the stock `sbin/ethernet.sh` (`patch_ethernet_hostname.sh`, fail-loud and idempotent) so both `udhcpc` starts use it, with a fallback to `akam`. No live DHCP restart: the router sees the name after the next boot or lease. `akam_hwcheck.sh` reports it. Tests: `tests/hostname_test.sh`. The 8091 `SET sys.hostname` of the V1.1 control API will reuse the same file and script.
- Wizard terminal UI, pure bash with no extra dependency: on a real terminal `./akam` opens a full-screen, keyboard-driven menu (status icons done/todo/blocked/stale, arrows or `j`/`k`, Enter runs, `?` explains what/why/risk, `r` picks several steps with checkboxes, `q` quits) with a header showing the host OS, the camera address and the kit/image; the questions become widgets (card picker, flash-route choice, yes/no, visible or hidden text, typed `ERASE <device>` / `YES` box that never accepts a shortcut key), long jobs show a spinner with elapsed time and a progress bar when a percentage is known (download), and failures show a panel with the exact failed command and the next step. The Wi-Fi password prompt now asks "Show the password while typing? [Y/n]". Terminal state is restored on exit, Ctrl-C and errors; it follows window resizes, fits 80x24, falls back to ASCII icons without a UTF-8 locale, honours `NO_COLOR`, and `--plain` (or `AKAM_PLAIN=1`, or no terminal) keeps the previous line-based UI unchanged. New: `tools/wizard/lib/tui.sh`, `tools/wizard/lib/tui_menu.sh`, `tests/wizard_tui_widgets_test.sh`, `tests/wizard_tui_pty_test.sh`.
- `ak_rtsp` frees its single client slot: before PLAY a client is dropped after 20 s without a complete request ("idle before PLAY") or if it needs more than 60 s to reach PLAY; a client that is playing is never dropped for idleness (write stall, disconnect, BYE and TEARDOWN as before). Host test `tests/rtsp_idle_test.sh`.
- Optional RTSP password (Digest login, RFC 2617 MD5 without `qop` for VLC/live555, ffmpeg, go2rtc and Frigate), **off by default**. `ak_rtsp` reads `/etc/config/akam/rtsp_auth` (`user:akam:HA1`, never the password) at every protected request: absent = open stream as before, valid = Digest required on everything but `OPTIONS`, damaged = everything refused. Per-connection random nonces, constant-time comparison, delays and a connection limit on failed attempts, no secret in the journal, no restart needed. New camera command `akam_rtsp_auth.sh` (`set`, `set-hash`, `show`, `status`, `disable`), `./akam rtsp-auth [set|disable|status]` (the password is typed and hashed on the PC; only the hash goes over SSH) and an opt-in question at the end of `verify` (default: No); `akam_hwcheck.sh` reports whether it is on. Never managed through port 8091. See `specs/03-spec-rtsp-auth.md`.
- Wizard core `./akam` (bash, English, Arch and Debian/Ubuntu): step menu with done/todo/blocked status, `doctor`, `get-kit` (checksum + signature via `verify_kit.sh`), `build`, `prepare-backup-sd`, `backup`, `image` (hardware verdict, stock compression, typed `I UNDERSTAND THIS IS UNTESTED`), `prepare-flash-sd`, `wipe-sd`, `--dry-run`, resumable state with stale-input detection, secret-free log.
- Wizard camera steps: `find-camera`, `backup` (double read on the camera, checked, copied to the PC with `nc` and hash verification, hardware fingerprint), `flash` (maintenance telnet with a typed `YES` relayed from the human, or SSH reflash), `verify`, `update`, `restore`; scripted telnet session over bash `/dev/tcp` (`camsh.sh`) with automatic manual fallback after 2 failures, verified retried transfers (`transfer.sh`), and a fake camera for the tests (`tools/wizard/fake_camera.sh`). The telnet flash checks the 8-partition layout first and keeps writing if the link drops (HUP ignored on the camera, INT/HUP/TERM ignored on the PC while it writes); camsh drops the BusyBox line-editor echo (tested against the real BusyBox telnetd).
- Host dependencies for Arch and Debian/Ubuntu: `check_host.sh` (per-distro install command, `--profile`, `--json`), `bootstrap.sh` (per-arch Zig pin incl. aarch64, `--print-plan`, `--offline`, retries on transient 5xx), `env.sh` exports everything that exists even without Zig, `check_time32.sh` picks an ARM-capable gdb (`gdb-multiarch` on Debian/Ubuntu).
- Debian 12 / Ubuntu 24.04 portability: POSIX awk only in `check_time32.sh` (no gawk `or()`), shellcheck 0.9 clean (SC2015), and `tools/ci/distro_check.sh` re-runs the whole build and local check in clean containers.
- microSD preparation on Linux: `tools/sd/sd_card.sh` (`list-candidates`, `prepare --mode backup|first-boot|flash-files`, read-only `verify`, `wipe`) with a `backend_linux.sh` (sysfs size, USB/SD-only guards, typed `ERASE <device>`, `--dry-run --stage-dir`); `prepare_first_boot_sd.sh` is unchanged. macOS is deferred.
- Added `tools/lib/host.sh` (Linux host helpers) and `tools/ci/local_check.sh` (local shellcheck + tests + tracked-file hygiene check).

The project was called Camyn during early development. Everything user-visible was renamed; the
flash layout, ports, the `ak_rtsp` binary name, the 8091 protocol and the persistent key files under
`/etc/config/dropbear/` are unchanged, so an existing camera keeps its host key and `authorized_keys`
after a reflash.

| Former name | New name |
|---|---|
| `CAMYN_*` environment variables and flags (`CAMYN_ROOT`, `CAMYN_FLASH_I_KNOW`, ...) | `AKAM_*` |
| `camyn_*.sh` scripts (`camyn_ssh.sh`, `camyn_lockdown.sh`, `camyn_hwcheck.sh`, `camyn_reflash_ssh.sh`) | `akam_*.sh` |
| `docs/camyn_v1_*.md`, `specs/*-camyn-v1.md` | `docs/akam_v1_*.md`, `specs/*-akam-v1.md` |
| SD card folder `camyn/` (with `authorized_keys`) | `akam/` |
| SD card flag file `CAMYN_MAINTENANCE` | `AKAM_MAINTENANCE` |
| On the camera: `/usr/local/camyn/`, `/tmp/camyn_*` | `/usr/local/akam/`, `/tmp/akam_*` |
| `LICENSE.camyn` in the image | `LICENSE.akam` |

### Release kit

- `tools/release/{make_kit,sign_kit,verify_kit}.sh`: build, sign (`ssh-keygen -Y`) and verify the
  prebuilt-binaries kit (`akam-kit-<version>.tar.xz`, Akam's own files only, never a firmware image);
  see `docs/akam_v1_kit.md`.
- The kit ships `supported_hardware.txt` (validated: LSC 3215672.3 / SI D26228 with its stock APP fingerprint; untested: 3215672.2 and anything else), hashed in `MANIFEST.txt`.

- `src/ak_rtsp/build_firmware.sh --kit DIR|TARBALL` assembles the image from a verified kit (no compiler); source and kit modes install the Akam files from the same `tools/release/image_files.txt`. The image follows the stock APP compression (xz or gzip, block size, BCJ) read from the dump, `--comp` overrides it with a loud warning, other compressors are refused. The dump is compared with `supported_hardware.txt`: anything but `validated` is refused without `--i-understand-untested`, another MTD layout always. Verdicts and fingerprints go to `build_report.txt`. `tools/image/assemble_from_kit.sh` wraps it for a backup directory. A kit directory (no signature to check) needs `--allow-unsigned` like an unsigned tarball; a release kit's time64 gate is replayed on the installed binaries when gdb is present; a kit carrying overlay files this script does not install is refused; the backup must hold `mtdblock0..7.bin` and a readable uImage kernel for a `validated` verdict.

### Deprecated aliases (removed in the next release)

An SD card prepared before the rename still works with the new image:

- `akam_ssh.sh` reads `camyn/authorized_keys` when `akam/authorized_keys` is absent and logs a
  `DEPRECATED` line in `/tmp/akam_ssh.log`.
- The file `CAMYN_MAINTENANCE` at the card root is accepted as `AKAM_MAINTENANCE` by the patched
  `service.sh` (SD hooks and the RAM marker), by `akam_lockdown.sh` (logs `DEPRECATED`) and by
  `akam_hwcheck.sh` (prints a `WARN`). Build without the alias with `AKAM_MAINT_FLAG_LEGACY=`.
- `flash_guard.sh` accepts `CAMYN_FLASH_I_KNOW=1` as `AKAM_FLASH_I_KNOW=1`, with a warning.
- `patch_service_sh.sh` recognises daemon lines already disabled with the former `CAMYN-DISABLED:` marker.

What to change on your side: rename the `camyn` folder and the `CAMYN_MAINTENANCE` file on your SD
card, use the new script and variable names, and (optionally) rename your local `~/.ssh/camyn` key
and the `~/camyn-backup` / `~/camyn-work` / `~/camyn-sdprep` directories that the docs now call
`~/.ssh/akam`, `~/akam-backup`, `~/akam-work` and `~/akam-sdprep` (`prepare_first_boot_sd.sh` looks for
the toolkit clone in `~/akam-sdprep/toolkit` by default: pass `--toolkit ~/camyn-sdprep/toolkit` to reuse an old clone).

akam - guided setup for Akam, for the LSC Indoor 1080p and the LSC Rotatable 2K (PC side)

Usage: akam [options] [command]

Commands:
Install, 1080p (the nine steps, in this order):
  (none)             home screen: choose the camera, set up, update, options, backup, settings
                     (on a terminal: a full-screen menu, keys: arrows or j/k, Enter, ? help, c camera, q)
  steps              the nine setup steps with their status, one at a time; resumes where you stopped
  doctor             check this computer (tools); changes nothing
  get-kit            download and verify the prebuilt kit (no compiling)
  build              build from source instead (optional, needs more tools)
  prepare-backup-sd  prepare the microSD card used to back up the camera
  find-camera        find the camera (asks its IP address, checks the ports)
  backup             back up the camera (double read, checked, copied to <backup folder>/Akam backups/<name>/<date>/),
                     or accept a backup folder you made by hand (--backup-dir DIR)
  image              build the Akam image from your backup
  prepare-flash-sd   prepare the microSD card used to flash the camera
  flash              write the image to the camera (SSH when Akam runs, else maintenance telnet)
  verify             check SSH, ports and hardware, then the same without the card
Install and update, 2K (card-less; in this order: prepare-2k-sd, backup-2k, seed-2k, appfs-build, appfs-flash, then key-2k after the first card-less boot):
  prepare-2k-sd      2K only: prepare the first-install microSD card from the signed 2K kit (no flash is written;
                     --kit FILE or the newest release; asks the SSH key, the Wi-Fi and the red-box yes/no).
                     The card disables the rescue telnet (akam/no_telnet); --rescue-telnet keeps the passwordless
                     root telnet of the card (port 23) for a rescue card
  backup-2k          2K only: back up the six flash partitions over SSH (read only, each read twice, checked),
                     kept like the 1080p backup in <backup folder>/Akam backups/<camera>/<date>[-N] (private,
                     with SHA256SUMS, README.txt, camera_info.txt); --out DIR for another new folder
  seed-2k            2K only, once, while it runs from the first-install card and BEFORE appfs-flash: copy the Wi-Fi
                     settings and the SSH key of the card into the camera's /config/akam (done on the camera; nothing
                     is shown or kept on this PC; a file already there is never overwritten; needs the SSH key set up)
  appfs-build        card-less 2K only (--model lsc-rotatable-2k-ak3918av130): build the appfs image from your
                     mtd3.bin backup and the 2K kit (--backup-dir DIR [--out DIR]); host only, any OS. The kit is the
                     signed .tar.xz given with --kit FILE (verified), else the newest release (or --version X.Y.Z)
                     downloaded and verified; --kit DIR takes an unpacked folder you made yourself
  appfs-flash        card-less 2K only: rehearse (default) or write that image to mtd3 (--image-dir DIR
                     --backup-dir DIR [--current-image FILE --hot|--hot-preflight] [--nvram] [--execute]);
                     --execute needs a terminal, the recovery acknowledgement and a typed confirmation
  key-2k             2K only: have the camera create the admin API key of this assistant and keep it on this PC
                     (0600, never shown); every 2K setting and `update` need it
Update and go back (both cameras):
  update             flash a new image over SSH (no card). Choose the firmware with --version X.Y.Z (a published
                     release), --kit FILE, --image FILE or --stock (back to the original); without one, the menu
                     asks "Which firmware?"
                     On the card-less 2K it is one flow: reads the model and version over the signed API
                     (--api-key-file FILE), verifies the kit (--kit FILE, --version X.Y.Z), builds the image from
                     your backup (--backup-dir DIR), shows what changes, rehearses without writing, asks, writes,
                     waits for the camera after YOU power-cycle it and checks mtd3 and the version. The previous
                     image is kept: update --rollback puts it back. --current-image FILE names the image on a
                     camera flashed by the scripts, --card updates from an SD card boot, --force allows a
                     downgrade, --yes answers the rehearsal and the typed question only (never the recovery
                     question, which needs --recovery-at-hand as well); a terminal is always required
  restore            1080p: put the original APP back from your backup (the 2K goes back to stock by flashing your own mtd3.bin, see docs/porting/lsc-rotatable-2k/README.md)
Backups, firmware source (both cameras):
  backup-location [show | DIR | default]
                     where backups are kept (both models, no menu): show the folder and the next backup's folder,
                     set an existing folder that will hold 'Akam backups' (refused inside a git tree; a cloud-synced
                     folder needs a yes, or --yes), or go back to the default (Documents, else the home folder).
                     A setting of the camera in use (--camera NAME for another)
  import-backup      --from DIR [--camera NAME] [--model 1080p|2k] [--date YYYYMMDD] [--record] [--dry-run]
                     bring a backup you already have (1080p mtdblock0..7.bin, 2K mtd0..5.bin; SHA256SUMS or MD5SUMS
                     if present must match, sizes must match the model, a partial one is refused) into
                     <backup folder>/Akam backups/<camera>/<date>[-N]: COPIED (the source is never changed or
                     removed), SHA256SUMS, README.txt, camera_info.txt added when missing, the copy re-verified.
                     The date is the folder name's, else the files' (or --date). The same backup already under the
                     camera is reported, not copied twice. --record makes the copy the camera's backup (the 2K's
                     for update). --dry-run lists exactly what would be done
  trust-key [list | add FILE.pub [--name LABEL] | remove LABEL]
                     the extra signing keys you trust for your own firmware builds (ed25519; asks before adding)
  release-source [show | owner/name | default]
                     the GitHub repository that get-kit, update and appfs-build download from (default: the official one)
  releases           list the firmware releases published on GitHub for your camera model, newest first
                     (read only; --include-prereleases)
Settings of the camera in use, 1080p (the 2K block follows; talk and say work on both):
  hostname [NAME]    give the camera its network name (default: the camera's name), over SSH;
                     applied at the next power cycle (needs a firmware that has akam_hostname.sh)
  rtsp-auth [set|disable|status]
                     password (Digest login) on the video stream, over SSH; off by default
                     (typed here, never shown, sent to the camera only as a hash); default: status
  led [show | status on|off|auto] [ir auto|off]
                     the front LED and the infrared night LEDs, through the camera's signed API; saved on the camera. Default: show.
                       status: on (as now), off, or auto (blinks while starting or without Wi-Fi, blinks
                       slowly while someone watches the video, solid otherwise)
                       ir: auto (IR LEDs light at night) or off (never lit; night mode still switches the image)
  audio [show | volume 0-100 | beep | on | off | talk on|off | mic on|off]
                     the camera's speaker and microphone, through the camera's signed API. Default: show (volume, speaker on/off,
                     talk on/off, microphone on/off, playback underruns and drops). volume, talk and mic are
                     saved on the camera; mic off never opens the microphone and removes the audio track from
                     the stream (needs a reboot to apply); beep plays a
                     short tone; off silences the speaker and keeps it off after a reboot; on may need a
                     reboot of the camera to start the speaker. No confirmation is asked.
  picture [show | brightness N | contrast N | saturation N | sharpness N | denoise N | wb conf|manual | night auto|day|night | flip|mirror|ceiling on|off | reset]
                     the picture, through the camera's signed API. N is -50 to 50 (0 = unchanged); the four numbers, wb (/etc/config/akam/image)
                     and night (/etc/config/akam/night) are saved on the camera and applied at every start.
                     reset puts the four numbers back to 0 (sharpness -15, denoise 2). denoise N is 0 to 4: 0 = the camera's own
                     noise reduction, 2 = default (1080p: each light level uses the 3D noise-reduction tables of the
                     level 2 steps higher). flip (vertical), mirror (horizontal) and ceiling (both) are on or off, saved on the camera and
                     applied at once (1080p: not yet verified on a camera). Several words can be combined. Default: show.
  video [show | bitrate N | fps N | gop N]
                     the video encoder settings, through the camera's signed API. Default: show. bitrate is the cap in kbit/s (500 to 3000,
                     default 1536); fps is 10, 15, 20 or 25 (default 15; night mode always runs at 10); gop is the key
                     frame interval in seconds (1 to 4, default 2). Saved on the camera, applied at the next restart of the video service: you are
                     asked (default No) whether to restart it now (the stream stops for a few seconds).
                     Resolution is not available (flip and mirror: see picture).
  control-port [status | open | close]
                     the text port 8091 of the 1080p listens on the camera itself only (the settings go through
                     the signed API, port 8092). 'open' (asks first, default No) opens it to your network for
                     monitoring tools: no password, reads only; the video service restarts to apply it. 'close'
                     closes it again. Default: status
  api-key [status | replace]
                     the API key of this PC for the camera. The first command that needs it asks (default No)
                     to create it over SSH, once: an admin key named 'assistant' whose secret stays in your state
                     folder and is never shown. 'replace' revokes the old one and makes a new one. On a 2K: key-2k
  ntp [status | set SERVER... | off]
                     time sync of the camera (it has no clock of its own and starts in the past), over SSH.
                       set: 1 to 3 servers (host names or IPv4 addresses, for example ntp.example.net); the camera
                       asks them at start-up and every 6 hours (UDP 123, outgoing only) and saves the choice
                       off: stop and forget the servers (default: off, no traffic at all)
                       status (default): servers, the camera's clock, whether it is believable
  onvif [enable [PORT] | disable | status]
                     ONVIF for NVRs and apps (ONVIF Device Manager, Frigate, Home Assistant): off by default.
                     'enable' (asks first, needs the stream password: rtsp-auth set) opens TCP PORT (default 80)
                     and UDP 3702 on your network; 'disable' closes them. Over SSH. Default: status
  mqtt [status | set | disable | forget | test]
                     optional MQTT client for Home Assistant (a broker on your network): off by default, over SSH.
                       set: asks the broker address, port, user name and password (not shown), then asks (default No)
                         whether to turn it on; the camera connects OUT (no new open port), in plain TCP
                       disable: stop (the settings stay); forget: stop and delete the settings and the password
                       test: one connection attempt with the saved settings; status (default): on or off, the broker
  key [show | use-shared | use-new | use FILE.pub]
                     the SSH key that opens this camera (each camera can use the shared key ~/.ssh/akam, a key of its
                     own ~/.ssh/akam-<name>, or any ed25519 key). Default: show (which key, its fingerprint).
                     use-*: over SSH, adds the new public key to the camera, logs in again with it, and only then
                     remembers it for THIS camera; then asks (default No) whether to remove the old key from the
                     camera. If anything fails the camera still accepts the old key. Other cameras are not touched.
                     A new key is made on this computer (ed25519, passphrase asked twice, private file mode 600).
  config [show | save-global | save-local | apply | edit-global | forget-secrets]
                     the settings of a camera, saved on THIS computer: a global config (the default template for
                     new cameras, profiles/global.conf) and, per camera, its local config (what was last read or
                     applied). A config holds the Options settings (video, picture, LED, audio, ONVIF, time sync,
                     MQTT, video password on/off and user name) and the SSH key choice. Passwords and the Wi-Fi are in
                     a separate private file that exists only if you say yes (default No) each time you save.
                       show [--global]: what is saved (passwords shown as set / not set, never their value)
                       save-global [--from CAMERA]: read a camera now (or what was last saved for it) into the
                         global config; asks (default No) to keep the passwords, and the Wi-Fi, in it
                       save-local: record this camera's settings as its local config
                       apply --global | --from CAMERA [--only video,picture,led,audio,onvif,ntp,mqtt,auth,key]
                         [--include-secrets]: compare with the camera, show the differences, ask (default No),
                         then send them as the Options screens do; the video restart is asked separately.
                         A password is sent only with the setting that needs it (it cannot be read back).
                         Wi-Fi is never applied to a running camera (it only prepares the card of a new one).
                         The SSH key change and a removal of the video password each ask their own question.
                       edit-global: edit the template without a camera (session; a list in plain)
                       forget-secrets [--global]: delete the saved passwords and Wi-Fi of the global config, or of
                         this camera (--camera NAME), from this computer. Nothing is synchronised, ever.
  talk [SECONDS | test]
                     speak to the camera's speaker from this computer's microphone (Ctrl-C stops);
                     'test' sends a 2 second tone. Needs the stream password (rtsp-auth); the microphone is
                     built in on Linux (PulseAudio or PipeWire) and Windows (WASAPI), ffmpeg (or arecord on
                     Linux) otherwise; uses the ONVIF audio backchannel on port 554
  say FILE           play an audio file on the camera's speaker (ffmpeg converts it)
                     audio, talk and say work on the 1080p and the 2K (on a 2K: the speaker is off by default, `audio on`; no SSH needed)
Rotatable 2K settings (through its signed API, port 8092, key from key-2k; the same words as the registry keys):
  led, picture, video, hostname, audio, ntp, onvif, mqtt, rtsp-auth, talk and say work on a 2K, plus:
    led [show | status auto|on|off | ir auto|off]
    picture [show | brightness|contrast|sharpness 0-100 | saturation -50..50 | denoise 0-4 | wb conf|manual | mains 50|60 | flip|mirror|ceiling on|off]
    video [show | stream 0|1 | bitrate N | maxbitrate N | fps N | gop N | minqp N | maxqp N | rc vbr|cbr|avbr]
    hostname [NAME]    (no NAME: shows it)
    track [show | on|off | return stay|home | delay S | tilt on|off | lag MS]
    wifi [show | country CC|none | band 2.4|5]     (asks first, default No; --yes answers)
    settings [list | get KEY|PREFIX... | set KEY VALUE...]   the catalogue keys only, one PATCH for all
                     Values are checked like the camera does; its own refusal is shown. Nothing is created
                     here: without an API key the assistant says so (akam key-2k). --dry-run prints the PATCH.
  Refused on a 2K (1080p only): backup, restore, verify, image, flash, get-kit, prepare-backup-sd, prepare-flash-sd,
  config, key, control-port. api-key is key-2k.
Maintenance and information:
  wipe-sd            erase a card that holds your Wi-Fi password (use it when you are done)
  step NAME          run one step again (doctor, get-kit, prepare-backup-sd,
                     find-camera, backup, image, prepare-flash-sd, flash, verify)
  status             show every step: done / todo / blocked
  cameras            list the cameras you set up (one progress each); switch with --camera NAME
  rename-camera NEW  give the current camera another name (its progress moves with it)
  register           record a camera that ALREADY runs Akam, without redoing backup, image or flash:
                     ./akam --camera NAME --ip ADDRESS [--backup-dir DIR] register
  version            show the version of this program
  self-test          offline checks of the built-in parts (G.711, Digest, state files); changes nothing
  forget-host-key IP forget the remembered SSH host key of a camera (after a reinstall; asks first)
  licenses           show the licences of the software built into this program
  help               this text


Options:
  --dry-run          rehearse: show every command, change nothing, ask nothing
  --kit FILE         use a local kit (tarball with SHA256SUMS next to it, or folder)
  --version X.Y.Z    firmware release to download for get-kit, or to put on the camera with update
  --repo owner/name  get-kit, update, appfs-build, releases: download from this GitHub repository for this run
                     (the kit must still be signed by the official key or a key you added with trust-key)
  --name LABEL       trust-key add: the label of the key (default: its comment)
  --model ID         camera model of the kit (default: the model found by the backup, or the only one)
  --allow-unsigned   accept a kit without a signature (checksum only)
  --rescue-telnet    prepare-2k-sd: keep the passwordless root telnet on the card (rescue card only; default: disabled)
  --expect-sha256 H  require the kit sha256 to start with H (from the release notes)
  --backup-dir DIR   your backup folder (1080p: mtdblock0.bin ... mtdblock7.bin; 2K: mtd0.bin ... mtd5.bin)
  --backup-copy DIR  also copy the backup folder to DIR (another medium) and check the copy
  --ip ADDRESS       the camera's IP address (find-camera asks otherwise)
  --identity FILE    your SSH private key (default: ~/.ssh/akam, or --pubkey without .pub)
  --image FILE       1080p: image for update (default: the one built by the image step; exactly 5242880 bytes)
  --stock            update: put the original (stock) firmware back from your verified backup (the restore
                     command with all its gates; never tested on a real camera)
  --include-prereleases
                     releases and the firmware list: also show prereleases (hidden by default)
  --manual-telnet    never drive the camera's telnet shell: the wizard prints each command and
                     you paste it in your own telnet window (also automatic after 2 failures)
  --out DIR          where the image is written (default ~/akam-image-<name>-<date>)
  --builder native|tools
                     image builder: tools = the bash wizard (Linux, the default there); native = built
                     in this program from your backup (EXPERIMENTAL, not yet validated on hardware)
  --i-understand-untested
                     native builder: build even when the backup is not a validated target
  --comp xz|gzip     override the stock APP compression (not recommended)
  --allow-unknown-stock-comp
                     allow a stock APP compression other than xz/gzip (expert)
  --device DEV       whole microSD disk, for example /dev/sdb
  --pubkey FILE      SSH public key for the flash card (default: asked; the shared key ~/.ssh/akam.pub comes first)
  --ssid NAME        Wi-Fi name (the password is asked without echo, or set AKAM_WIFI_PASS)
  --profile P        doctor profile: kit | build | all
  --camera NAME      the camera to work on (a short name such as kitchen: a-z, 0-9, '-', at most 20).
                     Each camera has its own progress and log; a new name starts a new camera. The
                     name is used in the backup and image folders. The first menu run asks for it;
                     progress made before this existed is the camera called "default".
  --state-dir DIR    where progress and the logs are kept
                     (default ${XDG_STATE_HOME:-~/.local/state}/akam)
  --trust-new-host-key FP
                     accept the first SSH host key of a camera when its SHA256 fingerprint is FP
                     (without a terminal; a CHANGED key is always refused)
  --password-file F  read the stream password for talk/say from the first line of F
  --no-color         no colours (NO_COLOR works too)
  --plain            line-based output and prompts, no full-screen menu or widgets
                     (also automatic when not on a terminal; AKAM_PLAIN=1 does the same)

From a source checkout, build this program with tools/assistant/build.sh (it runs as tools/assistant/bin/akam).
The bash wizard (./akam in a source checkout, 1080p, Linux) will be retired; new features go to this program only.

Safety: this program never runs sudo (it prints the command; only the SD tool asks sudo
for the disk work), shows every command before it runs, refuses destructive actions without a
terminal, and never stores your Wi-Fi password. Erasing a card and writing the camera's flash
each need your explicit yes in a red box (one yes/no, default No: Enter, Esc or q mean No).
It never reboots or power-cycles the camera.
